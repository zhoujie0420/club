# 首版开发与 my-cloud 测试部署

本次交付为核心流程联调版，使用 UniApp / Vue 3 前端与 Go API。入口只注册新的员工工作台；旧演示页面源码保留，但不再作为可访问路由。

## 可以验证的功能

- 数据库员工账号和独立口令登录，12 小时测试会话；四个预置账号使用固定测试口令 `holeclub`。
- 店长可创建、启停员工账号并重置登录口令；停用或重置后，该员工现有会话立即失效。
- 店长可查看最长 90 天全店营业报表，销售只能查看本人订单汇总；报表包含营收、完成单、取消单、客单价和每日明细。
- 店长可新增、改名、改价、上下架商品与套餐；预订和加单从服务端读取当前价格，已成交订单保留当时价格。
- 销售、前台、服务员、店长四种角色；按钮按权限展示，服务端再次强制校验。
- 工作台：按北京时间 06:00 切换营业日，统计有效订单、待到店、使用中、已收金额。
- 18 个统一配置台位，按营业日查看、状态筛选、5 秒自动刷新。
- 两步预订：客户与日期 → 可用台位与套餐。
- 姓名、手机号、人数、台位、日期、预计时长和商品校验；同台同营业日允许相邻时段连续预订，重叠时段由服务端拒绝。
- 订单查询及待到店、进行中、已完成、已取消筛选。
- 确认到店 → 开台 → 加单 → 记录线下收款 → 完成清台。
- 店长确认线下退款完成后可分一次或多次登记部分退款；每笔必须选择原因并保存金额、时间和操作人，累计退款不能超过原收款，营业报表按净收入统计。
- 取消待到店预订、保存收款方式、实收金额、操作人和操作时间线。
- 审计日志记录每次创建、到店、开台、加单、结账和清台；店长可查看筛选后的最近 500 条，其他角色由服务端拒绝访问。
- 店长可按 1–90 天日期、员工及全部操作 / 收退款 / 仅退款筛选最多 500 条审计记录；营业报表和筛选结果均可导出带 UTF-8 BOM 的 CSV。
- 销售只读取本人创建的订单与业绩；前台、服务员和店长按门店范围协作。
- 订单备注、带原因取消预订、前台 / 店长改台；改台前校验容量与台位冲突。
- 销售可修改本人待到店预订，前台 / 店长可修改门店待到店预订；姓名、手机号、人数、日期、时间、时长和备注变更均重新校验并记录操作人。
- 服务端定价、数据库事务、并发占台约束、版本冲突检查和幂等请求。
- 退出登录同步注销服务端会话；服务重启后保留订单和未注销会话。

## 与目标架构的阶段差异

my-cloud 的 deploy 账号可运行用户服务，但无 Docker、系统 Nginx 和现有 MySQL 管理权限。本次使用独立 Go 进程和 SQLite 文件部署联调环境，避免修改现有系统服务。

当前不是完整 P0 正式营业版本：四个预置身份共用固定测试口令 `holeclub`，店长可逐一重置为独立口令；MySQL 数据模型、sqlc、Pinia 模块拆分、服务端分页、退款、并台、短信、会员和线上支付尚未实现。

四种测试身份使用固定 RBAC 权限。手机号接口可供测试搜索使用，尚未完成生产级字段加密与查看审计，请只录入虚构数据。当前商品价格以整数元计价；正式版应迁移为整数分。

台位使用简化区域布局，未接入真实场地平面图。预订现按到店时间和 1–12 小时预计时长（30 分钟粒度）判断冲突，跨午夜时段仍归属开始时的营业日。订单接口目前返回最近 1000 笔，适用于此测试环境，正式版需要分页与独立库存查询。

## 部署位置

- 云端测试地址：`http://115.191.3.226:18080/club/`。TCP 18080 已放行并通过公网浏览器验收。
- 当前电脑 SSH 转发入口：`http://127.0.0.1:18081/club/`，连接的是同一个云端服务。
- 重建转发：`ssh -N -L 18081:127.0.0.1:18080 my-cloud`，保持此命令运行。该入口仅对当前电脑有效。
- 四个预置身份（店长、销售小林、前台小周、服务员阿杰）使用固定测试口令 `holeclub` 登录。口令也写在远程 `service.env` 的 `CLUB_ACCESS_CODE`。这是测试环境口令，不要用于生产。

- SSH 主机：`my-cloud`，用户 `deploy`。
- 目录：`/home/deploy/club-test`。
- Go 可执行文件：`club-api`。
- 前端构建：`web/`，由 Go 服务托管 `/club/`。
- 数据文件：`club.db`，与发布产物分离，不随部署覆盖。
- 环境变量：`service.env`，仅部署用户可读。测试口令固定为 `holeclub`。
- 服务：`systemctl --user status club-test.service`。
- 日志：`journalctl --user -u club-test.service -n 100`。
- 重启：`systemctl --user restart club-test.service`。
- 已为 deploy 开启 linger，用户服务可在注销后及开机时运行。

## 构建与部署

```bash
cd front
npm ci
npm run type-check
npm run build:h5
cd ../server
GOTOOLCHAIN=go1.23.12 go test -race ./...
GOTOOLCHAIN=go1.23.12 GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -o ../.artifacts/club-api ./cmd/api
```

将构建产物上传到 `/home/deploy/club-test`，前端上传至 `web/`；首次部署同时上传 `deploy/club-test.service` 与 `deploy/install-test.sh`，在远程执行安装脚本。安装脚本仅在环境文件不存在时写入固定测试口令 `holeclub`，不覆盖已有口令和数据。

后续更新可先上传二进制为 `club-api.next`，然后替换 `club-api` 并重启用户服务，避免直接覆盖正在运行的可执行文件。

## 本地验证

```bash
# 先创建 .artifacts 目录，在仓库根目录运行
mkdir -p .artifacts
cd server
GOTOOLCHAIN=go1.23.12 PORT=18080 CLUB_ACCESS_CODE=local-test-only CLUB_DB_PATH=../.artifacts/local-test.db CLUB_WEB_DIR=../front/dist/build/h5 go run ./cmd/api

# 另一个终端
cd front
npx playwright install chromium
npx playwright test
```

E2E 覆盖移动端登录、预订、加单、结账、清台、第二个浏览器共享数据和 320/375/480 px 宽度检查。测试会产生带“自动验收”前缀的已完成订单，使用专用数据库运行。

已增加响应丢失场景：服务器已完成加单但浏览器未收到响应，重试仍只计入一份商品。

可在仓库根目录运行 `CLUB_TEST_URL=http://115.191.3.226:18080 node deploy/verify-remote.mjs`，对公网版本执行相同浏览器验收，并重启服务检查订单持久化。脚本通过 SSH 读取口令但不输出它。

## 验证顺序

1. 输入访问口令进入工作台。
2. 创建预订，使用测试姓名和虚构 11 位手机号，选择台位与套餐。
3. 在另一台设备登录，确认能看到同一笔订单。
4. 在订单详情依次确认到店、开台，添加一瓶啤酒。
5. 选择微信 / 支付宝 / 现金，确认线下收款，核对账单与收款方式。
6. 完成清台，切换到台位页确认台位变为空闲。
7. 创建另一笔待到店预订并取消，确认台位释放。

测试服务只记录线下收款，操作不会发起任何真实支付。
